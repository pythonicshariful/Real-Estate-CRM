Never-Expiring (স্থায়ী) Facebook Page Access Token তৈরি করার নিয়ম

সাধারণ টোকেন ১ ঘণ্টা বা ৬০ দিনে নষ্ট হয়ে যায়। এই পদ্ধতিতে আপনার টোকেন আজীবন সচল থাকবে!

★ পদ্ধতি ১: Meta Business System User (অফিসিয়াল ও সেরা পদ্ধতি)

Expires: Never
  1. ব্রাউজারে মেটা বিজনেস সেটিংসে যান: business.facebook.com/settings/system-users
  2. বামের মেনু থেকে Users > System Users এ যান।
  3. Add বাটনে ক্লিক করুন:
    • System Username: CRM Lead Automation
    • System User Role: Admin সিলেক্ট করে Create এ চাপুন।
  4. System User তৈরি হলে "Assign Assets" বাটনে ক্লিক করুন:
    • বাম থেকে Pages সিলেক্ট করে আপনার বিজ্ঞাপন চলা ফেসবুক পেজটি টিক দিন।
    • নিচে "Full Control" (Manage Page) টগল অন করে Save Changes চাপুন।
  5. এবার "Generate New Token" বাটনে ক্লিক করুন:
    • Select App: আপনার তৈরি করা CRM App টি বেছে নিন।
    • Token Expiration: ড্রপডাউন থেকে নির্বাচন করুন "Never" (স্থায়ী)।
    • Available Permissions তালিকায় এই পারমিশনগুলোতে টিক দিন:
      leads_retrieval pages_manage_ads pages_read_engagement pages_show_list
  6. নিচে "Generate Token" এ চাপুন। স্ক্রিনে একটি বিশাল টোকেন কোড আসবে (EAAB...)।
  7. টোকেনটি কপি করে আপনার সিআরএম-এর Settings > Meta Webhook > Page Access Token বক্সে পেস্ট করে দিন!

বিকল্প পদ্ধতি ২: Graph API Explorer এর মাধ্যমে পার্মানেন্ট পেজ টোকেন

বিকল্প
  1. যান: Graph API Explorer > Permissions এ leads_retrieval, pages_manage_ads, pages_read_engagement যোগ করে User Token তৈরি করুন।
  2. টোকেনটি নিয়ে যান: Token Debugger Tool > Debug চেপে নিচে "Extend Access Token" বাটনে ক্লিক করে ৬০ দিনের টোকেন বানান।
  3. পুনরায় Graph API Explorer এ এই টোকেন পেস্ট করে GET ফিল্ডে লিখুন: me/accounts?fields=name,access_token এবং Submit চাপুন।
  4. আপনার ফেসবুক পেজের নামের নিচে যে access_token পাবেন, সেটি সারাজীবন কখনোই এক্সপায়ার হবে না!
৪

App Secret ও পেজ সাবস্ক্রিপশন কনফার্ম করুন

ফেসবুকের পাঠানো তথ্যের নিরাপত্তা যাচাই ও পেজের সাথে লিংক নিশ্চিত করা।

⚠️ App Secret অবশ্যই মিলতে হবে — না মিললে লিড আসবে না!

CRM-এ সেভ করা App Secret আর Meta ড্যাশবোর্ডের বর্তমান secret না মিললে CRM প্রতিটি webhook 403 "Invalid signature. The App Secret does not match." দিয়ে ফিরিয়ে দেয়, আর Meta-র Testing Tool-এ দেখায় "Failure — Failure in webhook integration" / webhooks.delivery.rejected।

ঠিক করতে: Meta ড্যাশবোর্ড → App Settings → Basic → App Secret-এর পাশে Show (পাসওয়ার্ড দিয়ে দেখুন) → কপি করে CRM Settings → Meta-তে App Secret বক্সে পেস্ট করে Save করুন → তারপর নতুন টেস্ট লিড পাঠিয়ে যাচাই করুন।

  1. মেটা ডেভেলপার পোর্টালে App settings > Basic-এ গিয়ে App Secret কপি করে সিআরএম-এর Settings-এ সেভ করুন।
  2. পেজ সাবস্ক্রিপশন এখন স্বয়ংক্রিয়: CRM-এ "Connect with Facebook" করলেই OAuth callback পেজটিকে leadgen webhook-এ সাবস্ক্রাইব করে দেয়। হাতে করতে চাইলে Graph API Explorer-এ POST রিকোয়েস্ট পাঠান (অথবা টার্মিনালে রান করুন):
    curl -X POST "https://graph.facebook.com/v19.0/{PAGE_ID}/subscribed_apps?subscribed_fields=leadgen&access_token={PAGE_ACCESS_TOKEN}"
  3. যাচাই: Meta ড্যাশবোর্ড → Webhooks → Page-এ Callback URL সেভ আছে এবং leadgen ফিল্ডে Subscribed দেখাচ্ছে কিনা দেখুন।

কানেকশন টেস্ট ও লিড আসার প্রমাণ পরীক্ষা করুন

আপনার ফেসবুক লিড ইন্টিগ্রেশন ঠিকমতো কাজ করছে কিনা তা এই দুটি উপায়ে এখনই যাচাই করুন।

পদ্ধতি ১: সফটওয়্যারের ইন-অ্যাপ টেস্ট সিমুলেশন ইনস্ট্যান্ট

ফেসবুকে কোনো বিজ্ঞাপন রান না করেই সিআরএম নিজেই সম্পূর্ণ মেটা Webhook এর অনুরূপ ডাটা তৈরি করে লিড পরীক্ষা করতে পারে:

  1. সিআরএম-এর Settings > Meta Webhook ট্যাবে স্ক্রল করে নিচে নামুন।
  2. "Simulate Meta Lead (Webhook Test)" বক্সের ফরমটি পূরণ করুন।
  3. সবুজ "Simulate Lead Now" বাটনে ক্লিক করুন।
  4. সরাসরি Leads পেজে গিয়ে দেখুন লিডটি তৈরি হয়ে সেলস টিমের কাছে পৌঁছে গেছে এবং ৫ মিনিটের SLA কাউন্টডাউন শুরু হয়ে গেছে!
পদ্ধতি ২: ফেসবুকের অফিসিয়াল Lead Ads Testing Tool লাইভ মেটা টেস্ট

মেটার নিজস্ব সার্ভার থেকে আপনার সিআরএম সিস্টেমে লাইভ টেস্ট লিড পাঠান:

  1. ফেসবুকের এই লিংকে যান: Lead Ads Testing Tool
  2. আপনার Page এবং তৈরি করা Lead Form সিলেক্ট করুন।
  3. আগের কোনো টেস্ট লিড আটকে ("Pending") থাকলে সেটি আগে ডিলিট করুন — নইলে নতুন লিড বানাতে দেবে না।
  4. "Create Lead" বাটনে চাপ দিন — একবারে একটিই নতুন টেস্ট লিড পাঠান।
  5. RTU Status-এ "Success — Successful webhook integration" দেখা গেলেই বুঝবেন লিড CRM-এ পৌঁছেছে। তারপর CRM-এর Leads পেজে দেখুন (Source: "Meta Lead Ads")।
  6. নোট: Meta-র টেস্ট লিডে ডামি ডেটা থাকে — নাম "Meta Test Lead" আর ইমেইল test@meta.com দেখাবে। আসল লিডে আসল নাম ও তথ্য আসবে।

পরে ক্লায়েন্টের আসল পেজে কানেক্ট করা

টেস্ট শেষ হলে একই অ্যাপ দিয়ে আসল পেজে বদলাতে পারবেন — নতুন অ্যাপ লাগবে না।

  1. CRM-এ Settings → Meta ট্যাবে গিয়ে Disconnect চাপুন।
  2. "Connect with Facebook" চাপুন — OAuth ডায়ালগে ক্লায়েন্টের আসল পেজটি বেছে নিন। যে অ্যাকাউন্ট দিয়ে লগইন করবেন, সেটি ওই পেজের অ্যাডমিন হতে হবে।
  3. কানেক্ট হলে "Sync Forms" চাপুন — আসল পেজের lead form-গুলো sync হবে।
  4. বদলের পর Lead Ads Testing Tool দিয়ে একটি নতুন টেস্ট লিড পাঠিয়ে আবার যাচাই করুন (RTU Status "Success" হতে হবে)।
  5. নোট: আসল পেজের ফর্মের প্রশ্নের নাম Meta-র Standard Full Name / Phone Number হলে নাম-ফোন সরাসরি প্রোফাইলে ম্যাপ হবে; অন্য নাম হলে উত্তরগুলো লিডের "Custom Lead Form Answers"-এ দেখাবে।

প্রয়োজনীয় টিপস ও সাধারণ সমস্যা সমাধান

  • Webhook Verify না হলে: নিশ্চিত করুন আপনার সিআরএম সার্ভারে বৈধ HTTPS চালু রয়েছে এবং Verify Token হুবহু মিলেছে।
  • টোকেন ভ্যালিড কিনা দেখার উপায়: যেকোনো সময় Access Token Debugger এ পেস্ট করে দেখুন Expire ডেট Never লেখা আছে কিনা।
  • প্রশ্নোত্তরের উত্তর কোথায় দেখাবে: যেকোনো লিডের পাশে View Profile → ক্লিক করলে ডেডিকেটেড পেজে ক্যাম্পেইনের সব প্রশ্নের উত্তর সুন্দরভাবে প্রদর্শিত হবে।

❓ সচরাচর জিজ্ঞাসা (FAQ)

১. টেস্ট লিড "Pending — Lead publish in progress"-এ আটকে আছে, আসছে না কেন?

এটা Meta-র দিকের সমস্যা — লিডটি Meta-র সার্ভারেই publish হতে দেরি হচ্ছে, CRM-এ এখনো পাঠানোই হয়নি। অ্যাপ Unpublished থাকলে শুধু টেস্ট webhook আসে। কিছুক্ষণ অপেক্ষা করুন; না এলে Testing Tool-এ পুরনো লিডটি ডিলিট করে একটি নতুন টেস্ট লিড পাঠান।

২. RTU Status-এ "Failure — Failure in webhook integration / webhooks.delivery.rejected" দেখাচ্ছে কেন?

CRM-এ সেভ করা App Secret আর Meta ড্যাশবোর্ডের বর্তমান secret মিলছে না — তাই CRM webhook 403 "Invalid signature" দিয়ে ফিরিয়ে দিচ্ছে। ধাপ ৪ দেখে Meta ড্যাশবোর্ড (App Settings → Basic) থেকে বর্তমান secret নিয়ে CRM Settings → Meta-তে সেভ করুন, তারপর নতুন টেস্ট লিড পাঠান।

৩. লিডের নাম ফাঁকা বা "Meta Test Lead" দেখাচ্ছে কেন?

৪. Sarah শুধু নিজের লিড দেখে, Admin সব লিড দেখে কেন?

এটাই নিয়ম: Lead Owner শুধু নিজের assigned লিড দেখতে পারে, আর Admin সব লিড দেখতে পারে। এতে প্রত্যেকের কাজ আলাদা থাকে।

৫. ক্যালেন্ডারের ইভেন্টের রং কে সেট করে?

শুধু Admin। Admin Team পেজ থেকে প্রত্যেক Lead Owner-এর রং সেট করেন; Lead Owner নিজের রং বদলাতে পারে না। এতে Admin ক্যালেন্ডারে রং দেখেই বুঝতে পারেন কোন ইভেন্ট কার।

৬. SLA ব্যানারে "৫ মিনিটে breach" বলছে কেন?

লিড assign হওয়ার ৫ মিনিটের মধ্যে প্রথম কল না করলে SLA breach ধরা হয়। লিড পাওয়ার সাথে সাথে কল করলেই SLA resolved হয়ে যায়।

৭. Settings-এ "Last payload received" মানে কী?

এটি শেষ Meta Inquiry (লিড) তৈরি হওয়ার সময় — শেষ webhook POST আসার সময় নয়। তাই নতুন লিড না এলে এই সময় বদলাবে না।

৮. ফর্মের কাস্টম প্রশ্নগুলোর জন্য কি CRM-এ কিছু সেটআপ করতে হবে?

না। প্রতিটি প্রশ্নের উত্তর নিজে থেকেই চলে আসে। Standard ফিল্ড (নাম, ইমেইল, ফোন, পেশা, সার্ভিস, প্রজেক্ট) সরাসরি প্রোফাইলে ম্যাপ হয়, বাকি সব উত্তর লিডের "Custom Lead Form Answers"-এ দেখায়। তবে নাম/ফোন ম্যাপ হতে ফর্মে Meta-র Standard Full Name / Phone Number প্রশ্ন থাকতে হবে — অন্য নামে প্রশ্ন করলে উত্তরটি Custom Answers-এ যাবে।

৯. CRM সেশন expire হয়ে গেলে কী করব?

আবার Admin হিসেবে লগইন করুন। ব্রাউজারের লগইন প্রতি ব্রাউজারে আলাদা — এক ব্রাউজারে লগইন থাকলেও অন্য ব্রাউজারে আবার লগইন করতে হবে।
